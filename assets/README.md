# 知识回响 · 3D 资产库

本目录与现有 index.html 独立。第一批资产为原创程序化低模，用于验证 glTF 载入和场景编排，不是 AI 精细建模成品。现有首页和 Canvas 渲染器本次未修改。

## 使用入口
- [资产登记表](catalog.json)：按 assetId 检索文件、分类、状态、来源及交互锚点。
- [颈椎场景配置](scenes/cervical_discussion.json)：实例位置与交互绑定初稿。
- [在线目录与模型预览](index.html)：逐个查看已登记的基础模型。
- models/common：书本等通用组件。
- models/characters：答主与评论者通用人物。
- models/props：桌椅等道具。
- models/environments：参考教学空间背景。
- models/knowledge：专业模型目录，待补充。

## 资产接入规范
优先使用 GLB；现有自建基础模型为单文件内嵌 buffer 的 glTF 2.0。Y 轴朝上、+Z 朝前、以米为单位，地面原点放在物件底部。保持对象独立；人物包含 speech_anchor，书本有 left_hinge 和 right_hinge；医学组织应可分别选择且不得虚构解剖关系。建议单个小型道具 < 2 MB，单个重点模型 < 8 MB，首屏资产总量尽量 < 15 MB（初始性能预算，不是硬性平台限制）。

## 状态及替换流程
1. pending：计划或候选，path=null，不得传给加载器。
2. starter：可加载的基础资产，尚未经视觉与许可最终审核。
3. approved：模型内容、视觉、交互、性能及授权均验收后设置。
4. AI 生成或下载新模型时，核对使用权限、来源链接、署名及许可原文，记录到 catalog.json；不要把未获许可的素材推到公开仓库。
5. 专业解剖模型需参考可靠来源并核对结构；生成式模型不能直接作为医学依据。
6. 保持 assetId 不变，更新 path/format/source/license/review；先在独立预览验收，再接入主原型。Three.js 加载时使用相对于页面的路径，GitHub Pages 项目站点不能使用站点根路径 /assets。
7. AI 后续只需输出已登记 assetId 与允许的实例配置；不得生成任意外链、虚构来源或直接执行代码。

## 计划中的高质量素材
优先替换人物、立体书、场景家具；再补齐经过核验的颈椎结构模型。相机及睡眠教具按实际知识案例决定是否制作；不是所有知识都需要 3D。
